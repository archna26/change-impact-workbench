# Change Impact Workbench
## IBM Bob 2.0 Hackathon — Legacy Retail Co Demonstration

---

### What This Is

The **Change Impact Workbench** is a reusable tool that helps developers
understand the blast radius of a proposed change in an unfamiliar legacy
codebase before they touch a single line of production code.

Given any starting artifact — a field name, a program name, or a copybook —
the workbench indexes the repository, traces evidence-backed relationships
across all source files, and produces a three-tier impact report:

| Tier | Meaning |
|------|---------|
| **Confirmed** | Token or structural pattern found at the cited path and line — a *source reference* claim |
| **Needs Review** | Predicate, write, or call site found whose behavioral effect requires human review or tests |
| **Unknown** | Areas static search cannot reach (dynamic calls, binding directories, copy members) |

The workbench currently supports **IBM i** (DDS physical files, RPG ILE, CL)
and **COBOL** (copybooks and programs) as the first two legacy language adapters.

### Repository: Legacy Retail Co

`Legacy Retail Co` is a fictional, representative retail application used to
demonstrate the workbench. Its source files under `src/` are **synthetic** —
modelled on real IBM i and COBOL conventions but never compiled or run on any
platform. Catalog evidence is genuinely extracted from those files by the
workbench engine. No IBM i or COBOL compiler was run at any point.

### Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    Change Impact Workbench                      │
│                      ciw_engine.py                              │
│                                                                 │
│  ┌──────────────┐   ┌──────────────┐   ┌───────────────────┐  │
│  │   Indexer    │   │  Traverser   │   │  Report Builder   │  │
│  │              │   │              │   │                   │  │
│  │ IBM i:       │   │ BFS from     │   │ impact_report.md  │  │
│  │  DDS fields  │──▶│ starting     │──▶│ change_checklist  │  │
│  │  RPG Dcl-F   │   │ artifact     │   │ regression_plan   │  │
│  │  CL CALL PGM │   │              │   │                   │  │
│  │              │   │ Detects:     │   │ Three tiers:      │  │
│  │ COBOL:       │   │  DEFINES     │   │  Confirmed        │  │
│  │  CPY fields  │   │  WRITES/READS│   │  Needs Review     │  │
│  │  CBL COPY    │   │  SQL_PRED    │   │  Unknown          │  │
│  │  CALL literal│   │  COPY_MEMBER │   │                   │  │
│  └──────────────┘   │  DIRECT/IND  │   └───────────────────┘  │
│                     │  CALLER      │                           │
│  artifact_catalog.json  ──────────┘                           │
└─────────────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
  Python simulation              Bob IDE assistant
  harness (pytest)               reviews Needs Review
  Actual pass/fail               items, drafts fixes
```

**What is automated:** Indexing, token search, SQL predicate extraction, call-site
detection, COPY reference detection, three-tier report generation.

**What requires human review (Bob-assisted):** Predicate semantics (safe vs broken
for the new value), business invariant identification, fix drafting, test completeness review.

**What the engine cannot detect:** Dynamic calls, binding directories, copy members
inside programs that do not use explicit COPY statements, PERFORM THROUGH ranges.

### Three Change Requests Demonstrated

| CR | Artifact | Language | Dependency Pattern |
|----|----------|----------|--------------------|
| CR-1 | `ORDSTS` field — add Hold (`H`) status | IBM i | Fan-out: one field → multiple batch consumers with different predicates |
| CR-2 | `PRICECALC` program — change rounding mode | IBM i | Fan-in: multiple callers → one service program |
| CR-3 | `BILL-RATE` field — widen PIC definition | COBOL | COPY fan-out: one copybook → multiple COBOL programs |

### Quick Start

#### Prerequisites
```bash
pip install flask pytest pytest-flask
```

#### Web application (interactive UI)
```bash
# From the BOB_HT/ directory:
python app.py
# Open: http://127.0.0.1:5000
```
The web UI provides the full 6-step guided workflow:
1. Describe the change
2. Browse/search the repository catalog and select an artifact
3. Trace impact (runs `ciw_engine.py` via the API)
4. Triage findings (Relevant / Not Relevant / Needs Investigation)
5. Build a change and regression checklist
6. Export a markdown report

Two sample walkthroughs are pre-loaded in the sidebar: **ORDSTS** (IBM i) and **BILL-RATE** (COBOL).

#### CLI (unchanged)
```bash
# Index the repository
python sim/ciw_engine.py --catalog

# IBM i: trace ORDSTS field across all consumers
python sim/ciw_engine.py --artifact ORDSTS --type field --lang ibmi

# IBM i: trace PRICECALC callers
python sim/ciw_engine.py --artifact PRICECALC --type program --lang ibmi

# COBOL: trace BILL-RATE across copybook consumers
python sim/ciw_engine.py --artifact BILL-RATE --type field --lang cobol

# Run default suite — all green (58 tests; demo tests excluded by pytest.ini)
python -m pytest tests/ -v

# Run the incomplete-change demo separately to see the intentional red output:
python -m pytest -m demo tests/test_incomplete_change.py -v
```

### Coverage Honesty Statement

> The Change Impact Workbench prototype uses deterministic text indexing and
> regex-based pattern search. It detects: field definitions in DDS/copybooks,
> token-level field and program references, SQL WHERE predicate text, RPG
> `Dcl-F`/`ExtPgm` declarations, CL `CALL PGM()` statements, and COBOL
> `COPY`/`CALL` statements. It does **not** perform: compilation, data-flow
> analysis, resolution of dynamic calls, analysis of binding directories,
> or semantic interpretation of business rules. Items requiring semantic
> review are classified as "Needs Review". Bob operates as an IDE assistant
> using the workbench output as grounding context — it is not embedded in
> the engine.
